## 4. Etykiety superklas

Kolejność klas jest stała: `SUPERCLASSES = ("NORM", "MI", "STTC", "CD", "HYP")`.

Algorytm (zgodny z benchmarkiem PTB-XL, `docs/decisions.md` D-004):

```python
statements = pd.read_csv(root / "scp_statements.csv", index_col=0)
diagnostic = statements[statements["diagnostic"] == 1.0]
code_to_superclass = diagnostic["diagnostic_class"].dropna().to_dict()   # np. "IMI" -> "MI"

def derive_superclasses(scp: dict[str, float], min_likelihood: float = 0.0) -> list[str]:
    found = {code_to_superclass[c] for c, lik in scp.items()
             if c in code_to_superclass and lik >= min_likelihood}
    return [c for c in SUPERCLASSES if c in found]
```

- `likelihood` (0, 15, 35, 50, 80, 100; 0 = nieznane) **domyślnie ignorujemy** (`label_min_likelihood = 0.0`). Inny próg to wariant eksperymentalny.
- Kody rytmu i formy (np. `SR`) nie wpływają na superklasy.
- Rekord może mieć 0–5 superklas. Rekordy z 0 superklas zostają w indeksie (`n_superclasses = 0`),
  ale w zadaniu głównym są **wykluczane** z train, val i test (`data.drop_unlabeled = true`), jak w benchmarku.
- Wektor celu: `y ∈ {0, 1}^5` w kolejności `SUPERCLASSES`, `float32`.

## 5. Split i niezmienniki

```python
SPLIT_FOLDS = {"train": (1, 2, 3, 4, 5, 6, 7, 8), "val": (9,), "test": (10,)}
```

Niezmienniki sprawdzane automatycznie (`cardioai.data.contract.check_index_invariants`, T104):

1. Każdy `ecg_id` występuje dokładnie raz; `strat_fold ∈ {1, …, 10}`.
2. Zbiory `patient_id` w train, val i test są rozłączne.
3. Kolumna `split` wynika wyłącznie z `strat_fold` według `SPLIT_FOLDS`.
4. Kolumny etykiet są binarne, a `n_superclasses` równa się ich sumie.
5. Statystyki (normalizacja, `pos_weight`, metadane) mają w pliku źródłowym `split: "train"`.

Dostęp do `split="test"` przechodzi przez `cardioai.data.test_lock` i bez odblokowania kończy się wyjątkiem
`LockedSplitError` (`docs/evaluation.md` §7).

## 7. Sygnał: odczyt, jednostki, kolejność odprowadzeń

- Odczyt: `wfdb.rdsamp(str(root / filename))` → `(signal [T, 12] float64, fields)`; `fields["fs"]`, `fields["sig_name"]`, `fields["units"]`.
- Jednostka: **mV** (`fields["units"]` musi być `mV`). Rozdzielczość 1 µV/LSB.
- Po odczycie: transpozycja do `[12, T]` i rzutowanie na `float32`. Bez przycinania amplitud.
- Kolejność kanonyczna:
  `LEADS = ("I", "II", "III", "aVR", "aVL", "aVF", "V1", "V2", "V3", "V4", "V5", "V6")`.
  Nagłówki PTB-XL używają wielkich liter (`AVR`, `AVL`, `AVF`) — mapujemy nazwy bez rozróżniania wielkości liter
  i **zawsze** porządkujemy kanały według nazw z nagłówka, nigdy według pozycji.
- Długość: `T = 1000` przy 100 Hz, `T = 5000` przy 500 Hz (`RECORD_SECONDS = 10`). Inna długość → `RecordFormatError`.
- Wartości nieskończone lub NaN → `RecordFormatError` z `ecg_id` w komunikacie.

## 8. Próbka z Dataset i pipeline transformacji

`PTBXLDataset.__getitem__` zwraca słownik:

| Klucz | Typ / kształt | Kiedy |
|---|---|---|
| `x` | `FloatTensor [12, T]` | zawsze; po pipeline |
| `y` | `FloatTensor [5]` | zawsze |
| `y_quality` | `FloatTensor [4]` | gdy `quality.weak_labels` lub `quality.synthetic.enabled` |
| `lead_mask` | `BoolTensor [12]` | zawsze; `True` = odprowadzenie obecne |
| `meta`, `meta_mask` | `FloatTensor [M]` | gdy `model.metadata.enabled` |
| `aux` | `dict[str, FloatTensor]` | gdy włączone głowy pomocnicze (T403) |
| `ecg_id`, `patient_id`, `fold` | `int` | zawsze |

Kolejność transformacji (jedna implementacja w `cardioai.data.preprocessing`):

| Krok | Przestrzeń | Operacja | Train | Val/Test/Inferencja |
|---|---|---|---|---|
| 1 | mV | odczyt i kolejność kanonyczna (§7) | ✓ | ✓ |
| 2 | mV | resampling do `fs` modelu (tylko gdy wejście ma inne `fs`) | — | ✓ |
| 3 | mV | korupcje syntetyczne z etykietami jakości (T302) | opcjonalnie | tylko w robustness |
| 4 | mV | filtr zerofazowy (pasmowy, notch) — wariant ablacyjny | opcjonalnie | identycznie jak w train |
| 5 | mV | augmentacje fizyczne: `amplitude_scale`, `baseline_wander`, `gaussian_noise`, `time_shift` | ✓ | — |
| 6 | — | normalizacja (§9) | ✓ | ✓ |
| 7 | znorm. | augmentacje w przestrzeni znormalizowanej: `lead_dropout`, `temporal_mask` | ✓ | — |
| 8 | znorm. | maskowanie brakujących odprowadzeń (§13) | ✓ | ✓ |
| 9 | — | `torch.from_numpy`, `float32` | ✓ | ✓ |

Przypis do kroku 3: w treningu korupcję wstrzykuje parametr `corruption` funkcji `build_pipeline` (T302). W ewaluacji (robustness T305, syntetyczny
val jakości T303) korupcję wstrzykuje parametr `robustness_corruption` funkcji `build_pipeline(train=False, ...)`, stosowany w kroku 3
**wyłącznie** przy `train=False`; augmentacje (kroki 5 i 7) przy `train=False` są nadal ignorowane (D-023). W inferencji żaden z tych parametrów nie jest używany.

Determinizm: losowość próbki pochodzi z `np.random.default_rng([seed, epoch, ecg_id])`. Epoka trafia do datasetu
przez sampler zwracający pary `(epoch, index)`, dzięki czemu wynik nie zależy od liczby workerów, a `persistent_workers=True` działa.

## 9. Normalizacja — plik statystyk

Tryby (`preprocessing.normalization`):

- `per_lead_train` (domyślny) — średnia i odchylenie per odprowadzenie liczone **tylko na train**, po kroku 4 (filtr), bez augmentacji i bez korupcji.
- `per_record` — z-score per rekord i per odprowadzenie (`eps = 1e-6`); bez pliku statystyk.
- `none` — tylko do testów i porównań.

## 10. Cache sygnałów

- Katalog `data/processed/ptbxl_v1.0.3_{fs}hz/`: `signals.npy` (`float32 [N, 12, T]`, surowe mV w kolejności kanonicznej,

- Niezgodny `index_sha256` → błąd z poleceniem przebudowy (`scripts/build_cache.py`).
- Odczyt z cache i z WFDB musi dawać identyczne tablice (test w T106).

## 13. Brakujące odprowadzenia

- Konwencja: brakujące odprowadzenie ma wartość **0.0 w przestrzeni znormalizowanej** i `lead_mask = False`.
- `lead_dropout` (trening) i test „missing lead” (robustness) stosują dokładnie tę konwencję (krok 7–8 w §8).
- Odłączona elektroda w świecie rzeczywistym (płaska linia w mV) to inny przypadek — korupcja `electrode_flat` w kroku 3,
  wykrywana przez quality gate.
- API v1 wymaga 12 odprowadzeń; wejście z mniejszą liczbą kanałów jest odrzucane (`docs/inference_api.md` §5).

## 14. Znane pułapki PTB-XL

1. `patient_id` jest zapisany jako float — porównania bez rzutowania dają błędne wyniki.
2. `scp_codes` to tekst słownika Pythona, nie JSON — używaj `ast.literal_eval`, nie `json.loads`.
3. Wiek ≥ 300 oznacza pacjenta powyżej 89 lat.
4. Wzrost i waga są w większości puste — imputacja musi być jawna (maska).
5. Nagłówki WFDB mają `AVR/AVL/AVF` wielkimi literami.
6. Foldy 9 i 10 przeszły ocenę człowieka i mają wyższą jakość etykiet niż 1–8 — różnice train/val są częściowo „naturalne”.
7. Kolumna `report` zawiera tekst diagnozy — nie może być cechą.
8. Wersja 100 Hz jest już zdecymowana; filtr notch 50 Hz ma sens tylko przy 500 Hz (Nyquist przy 100 Hz = 50 Hz).
9. Część rekordów nie ma żadnej superklasy (tylko rytm lub forma) — patrz §4.
